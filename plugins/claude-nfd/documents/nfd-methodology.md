## 概要

NFD 是「培育（Nurture）」AI agent，而不是「撰寫（Write）」它的開發方法。它處理傳統 Code-First（確定性管線）與 Prompt-First（靜態系統提示）抓不到的、專業知識的 3 個特性：

1. **隱性（Tacit）** — 遇到狀況才會浮現的判斷標準
2. **個人性（Personal）** — 專家特有的做法
3. **演進性（Evolving）** — 隨市場與技術不斷變化的動態性質

## 3 層認知架構

依揮發性與個人化程度把知識分層：

| 層 | 角色 | 更新頻率 | 管理形式 |
|----|------|----------|----------|
| 憲法層（Constitutional） | 身分與根本原則 | 低（恆久） | 角色定義、倫理、品質標準 |
| skill 層（Skill） | 針對任務的具體能力 | 中（每月～） | 模組化管理（以 .md 為單位） |
| 經驗層（Experiential） | 運作紀錄與案例記憶 | 高（每天） | 語意檢索對象 |

### 資訊流動機制

```
    ┌─────────────┐
    │  憲法層      │  ← 恆久的原則
    └──────┬──────┘
       ↑結晶化  ↓落地
    ┌──────┴──────┐
    │  skill 層    │  ← 模組化
    └──────┬──────┘
       ↑結晶化  ↓落地
    ┌──────┴──────┐
    │  經驗層      │  ← 每天的累積
    │  ┄┄共享記憶┄┄│
    └─────────────┘
```

- **落地（上→下）**：以憲法層、skill 層為基礎解讀工作輸入
- **結晶化（下→上）**：從經驗層的片段萃取模式，升級到 skill 層、憲法層
- **透過共享記憶協作**：各 skill 模組經由共享的經驗記憶互相連結

## 知識結晶化循環（KCC）

NFD 的核心流程。把每天零碎的對話紀錄轉成可重複使用的知識資產。

### 經驗累積的 6 個類別

| # | 類別 | 標籤 | 記錄什麼 |
|---|------|------|---------|
| 1 | 操作紀錄 | `[operational]` | 決定與動作的事實 |
| 2 | 推理軌跡 | `[reasoning]` | 判斷背後的邏輯與前提 |
| 3 | 模式觀察 | `[pattern]` | 反覆發生的事件的共同點 |
| 4 | 失敗原因 | `[error]` | 錯誤的根本原因與修正步驟 |
| 5 | 脈絡註記 | `[context]` | 專案背景或團隊特有的方針 |
| 6 | 洞見片段 | `[insight]` | 還沒整理、但將來可能重要的想法 |

### 結晶化的 5 個步驟

1. **[EXTRACT]** — 從累積的紀錄挖出可重用的主題，找出共同模式
2. **[STRUCTURE]** — 把萃取的資訊整理成模組化的 skill 形式
3. **[DE-CONTEXTUALIZE]** — 去除特定案例的專有名詞與情境，抽象成通用原則
4. **[VALIDATE]** — 由專家驗證，確認沒有過度擬合或邏輯矛盾
5. **[INTEGRATE]** — 把驗證過的 skill 納入版本控制，合併到 skill 層

### 與 plugin 8 個步驟的對應

plugin 的 8 個步驟，是把論文的 5 個步驟套到 Claude Code 時，把前處理（Step 1-2）與產出（Step 6）拆成明確的步驟：

| 論文 5 步驟 | plugin 8 步驟 |
|-------------|--------------|
| （前處理） | Step 1：讀設定、確認處理位置 |
| （前處理） | Step 2：收集資料（含 session 紀錄濃縮） |
| EXTRACT | Step 3：平行萃取（subagent） |
| STRUCTURE | Step 4：整合與去重 |
| DE-CONTEXTUALIZE | Step 5：防過度擬合 + 去脈絡化 + 比對既有規則 |
| VALIDATE | Step 5（AI 驗證）+ Step 8（人工驗證） |
| （產出） | Step 6：輸出結晶化報告 |
| INTEGRATE | Step 7：更新紀錄、清理暫存、Git commit |
| （回報） | Step 8：回報結果、等人確認 |

## 雙工作區模式

把運作環境與分析環境在邏輯上分開，避免認知干擾：

- **培育工作區（日常運作）** — 執行工作、累積經驗的地方
- **外科工作區（外科修正）** — 做資料分析、重構、結晶化的地方

### 分離的本質：認知脈絡的分離

**雙工作區的「分離」是認知脈絡的分離，不是檔案系統的分離。**

在日常開發 session 裡，開發者與 AI agent 處在為「目前這個任務」最佳化的認知狀態。結晶化需要讀大量紀錄、橫向萃取模式，是完全不同的認知模式。兩者混在同一個 session：

- context window 被資料分析吃掉，壓縮原本的工作脈絡
- 日常工作累積的隱含前提會讓模式萃取產生偏差
- 結晶化的中間結果會干擾日常判斷

所以要分開的是 **session（認知範圍）**，不是儲存（檔案系統）。auto memory、NFD trace 這類共享資源，本來就設計成兩個工作區都能存取，只要注意同時寫入的衝突即可。

> **常見誤解**：以為「在別的目錄工作」「用 git worktree 分開檔案」才是雙工作區的本質，但那只是手段之一。最簡單的做法是「在另一個 terminal 開新 session」，就算在同一個目錄，認知脈絡也是分開的。

### 在 Claude Code 的實現方式

1. **新 session**（建議、最簡單）：在另一個 terminal 啟動 `claude`，跑結晶化。同一個目錄沒關係——分開的是 session（認知脈絡），不是檔案系統
2. **git worktree**（隔離更嚴格）：用 `git worktree add` 分出上層專案的工作副本，在那邊跑結晶化。也想避免檔案編輯衝突時有用
3. **headless**：`claude -p` 本身就是獨立的 session，適合排程或一次對多台機器跑。權限要用 `Edit(<nfd-dir>/**)` 開放寫入

### 相關的分離：NFD repo 的獨立性

NFD 目錄（預設 `.nfd/`，可用 `/nfd-init` 改）是獨立 Git repo，目的是**資料的分離**（不把 NFD 經驗資料混進上層 repo），跟上面的工作區分離（避免認知干擾）是不同的關注點，不要混為一談。

### 合併流程

每週～每月看一次外科工作區的成果（結晶化報告），把有用的模式手動整合進培育工作區的規則與 skill。NFD repo 是獨立 Git repo，可以用 `git -C <nfd-dir> log` 看歷史、`git -C <nfd-dir> revert` 回滾。

## 成效指標

論文中金融分析師案例研究的結果[^1]（這不是 plugin 本身的直接成效，而是整套 NFD 方法導入效果的參考值）：

| 指標 | 導入前 | 導入後 | 提升 |
|------|--------|--------|------|
| 有用回應率（Utility Rate） | 38% | 71% | 87% |
| 案例召回次數（Case Recall） | 2 件 | 12 件 | 600% |

| 經驗層 | session 紀錄（JSONL）+ auto memory + NFD trace（`<nfd-dir>/traces/`） |

| 雙工作區 | 在新 session／git worktree／headless 執行結晶化 |
| 經驗累積 | session 紀錄（JSONL）+ auto memory + NFD trace + 選用的 MCP 工具 |
