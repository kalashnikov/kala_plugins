# archive — 把完成 / 放棄的點子移到紀錄表

用 `/feature-ideation archive FI-012 completed` 啟動。
歸檔位置是 **vault 本體末尾的 2 張表**（`## 已實作紀錄` / `## 不採用紀錄`）。不另開檔案。

## 步驟

### 1. 確定對象

從 vault index 找該 ID 的行。找不到就說「ID `FI-012` 不在 vault 中」並**中止**。

### 2. 確定去處

| 參數 | 去處 |
|---|---|
| `completed` / `done` / `已實作` / `完成` | 已實作紀錄 |
| `declined` / `不採用` / `放棄` / `no` | 不採用紀錄 |
| 自由文字 | 從內容判斷，**並向使用者確認要放哪張表** |
| 省略 | 用 `AskUserQuestion` 問「已實作 / 不採用」 |

重複、別名、併入上位項目都用**不採用紀錄**處理（不開第 3 張表）。
理由欄寫「合併：與 FI-021 重複。出處資訊移到 FI-021 的備註」這類內容。

### 3. 填必填欄（這是重點）

**已實作紀錄** `| ID | 名稱 | 完成日 | 證據 | 心得 |`

- **`證據` 不可留空**。PR 編號 / tag・版本 / commit / ADR 至少一項。
  多項用斜線分隔（`PR #72 / v0.12.0 / ADR-0004`）。
  不知道就**問使用者**。不要猜
- **`心得` 不可留空**。用一行寫實作中學到的事，特別是**登錄時的預想哪裡錯了**，
  或連到詳細檔、知識筆記

> 把 `心得` 設為必填不是為了形式。實際發生過「GO 判定 → ADR → 實作完成」2 小時就跑完，
> vault 的 index 卻停在原點，放在同目錄的試行紀錄也沒有任何一條從 vault 連過去的事故。
> **不連結就寫不了紀錄行**，用結構強制建立從實作回到 vault 的路徑。

**不採用紀錄** `| ID | 名稱 | 判定日 | 理由 | 復活條件 |`

- `理由` 必填
- `復活條件` 是「發生什麼就移回」。沒可能就明寫 `—`（與「空白＝未填」區分）

新行**加在最上面**（日期降冪）。

### 4. 從 index 刪除該行

`done` / `declined` 不留在 index。**不要留刪除線的墓碑行**。
ID 缺號查 2 張紀錄表就能解釋。

同時確認：

- `## 重新評估佇列` 若有該 ID 的行就刪除
- `## 優先挑選` 若列有該 ID，為了記錄「在挑選中就完成了」這件事，**不要動**
  （它是 `check` 改選觸發 T2 / T4 的判定依據）

### 5. 保留詳細檔

不做實體刪除。有的話在末尾追加：

```markdown
## 判定歷程

- **YYYY-MM-DD**: <completed / declined>。<簡短理由>
```

frontmatter 的 `status` 與 `updated` 也要更新。

### 6. 回報

用 2〜3 行說明更新處。紀錄表超過 60 行時，
加一句「請考慮按年移到 `<feature-ideas>/archive-<年>.md`」。

---

## 隔離條件觸發事項（不可放在 vault 的遺留事項）

`archive` 判斷時會出現「還不到放棄，但現在無法判斷」的項目。留在 vault 會爛掉。

> **重新評估時間能由自己決定** → 用日期寫進 vault 的 `## 重新評估佇列`
> **要等外部條件成立才能判斷** → 移出 vault

實際運作中出現過「2〜3 週後重新評估」「Phase 1 效果驗證後重新評估」「下次稽核時或 6 個月後」
「數天〜數週後 reevaluate」4 種，**能換成日期的只有 1 種**。
其餘在原理上無法用日期比對抓到，一寫成期限就沒人會注意而被放著。

### 移去哪裡

1. 有 `known-issues.md` 就放那裡
2. 沒有就找同等的容器（`TODO.md` 的 Deferred 節 / `BACKLOG.md` / GitHub Issues）。**用現有的**
3. 都沒有就在 **vault 同一層**新建 `known-issues.md`。
   不要放在 `<feature-ideas>/` 裡（違反檔名規則）。**新建前先問使用者一次**

   ```markdown
   # 已知遺留事項

   觸發條件成立前無法判斷的遺留事項。不設期限。

   ## <標題> (deferred, YYYY-MM-DD)

   - **狀況**:
   - **暫緩判斷的理由**:
   - **重新評估 trigger**: <發生什麼就重看>
   ```

4. 只有使用者拒絕新檔時，才在 vault 以狀態 `frozen` 保留。
   **不放進重新評估佇列**（不給假期限）。備註固定寫 `觸發條件: ...`

`frozen` 超過 5 項時，`check` 會建議切出去。
