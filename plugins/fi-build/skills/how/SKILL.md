# how

探索程式碼，回答「X 怎麼運作」。

改寫自 pstack（poteto）的 how。

範圍不清楚時，先說出你的理解再開始，使用者可以修正。

## 1. 探索

小範圍（一兩個檔案、單一函式）自己用 graft 查就好：`graft ask "<問題>" --source`，需要呼叫關係時用 `graft callers`。

大範圍（整個子系統、跨多個目錄）派一個唯讀子代理（Agent tool，`subagent_type: Explore`，或 `routine-worker`），交給它使用者的問題和下面這段說明：

> 你要替一位資深工程師寫架構說明。他沒碰過這一塊。請探索程式碼，寫出能讓他建立完整心智模型、可以放心開始改的說明：有哪些主要部件、各自負責什麼、資料和控制怎麼在它們之間流動、狀態存在哪裡、進入點在哪。每個說法都附 `file:line`。你只有唯讀權限。用繁體中文回答。

## 2. 呈現

呈現探索結果。可以依對話脈絡小幅修飾，但不要大改子代理的內容。每個說法保留 `file:line`。
